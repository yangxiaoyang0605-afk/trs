本仓库维护日照银行智慧消保平台投诉管理相关的静态 HTML 高保真原型，用于功能演示、业务评审、测试案例编写和后续系统验收。当前原型不是完整前后端工程，直接用浏览器打开 HTML 即可查看。

## 核心文件

| 文件 | 说明 |
| --- | --- |
| `日照银行_智慧消保平台_投诉原型.html` | 主原型文件，GitLab 发布时只同步这个文件 |

## 维护规则

1. 修改原型后，保持 `日照银行_智慧消保平台_投诉原型.html` 和 `index.html` 内容一致。
2. HTML 是预编译后的 React 产物，内部使用 `_jsx` / `_jsxs`，不要直接写未编译 JSX。
3. 工作区长期存在一些无关删除和未跟踪文件，提交前必须确认暂存范围。
4. GitHub 主仓库通常提交 `日照银行_智慧消保平台_投诉原型.html`、`index.html`，以及用户明确要求维护的文档。
5. GitLab 镜像仓库只同步并提交 `日照银行_智慧消保平台_投诉原型.html`，不要把 `index.html` 或本 README 带过去。

## 系统功能操作手册

本手册按系统菜单和真实业务操作整理，用于后续编写测试案例、检查功能完整性和进行业务验收。写测试案例时，可以直接按每个模块的“入口、功能说明、操作步骤、业务规则、结果表现”拆分。

## 产品框架概览

当前原型围绕投诉工单全流程搭建，核心链路为：工单录入、派发、处理、客户联系、短信审核、处理结果审核、回访、台账报表和统计分析。

主要模块：

| 模块 | 功能定位 |
| --- | --- |
| 投诉管理 | 录入工单、处理工单、申请处理、台账报表、统计分析，是投诉业务的主流程入口 |
| 台账导出 | 按数据范围查询工单台账，支持勾选导出台账和附件 |
| 报表管理 | 展示处理状态、工单类型、投诉标签、处理统计、客服系统、监管转办、未办结等报表 |
| 统计分析 | 按全行、机构、产品、原因、渠道等维度查看投诉趋势和办理质效 |
| 后台管理 | 维护用户、机构、角色权限、字段码值、短信模板、节假日、标签等基础配置 |
| 移动端原型 | 面向工单投诉处理后审核流程，展示工单列表、工单信息、审核通过/不通过及理由录入 |

当前重点业务设计：

1. 工单列表保留 `我的待办` 和 `全部工单` 两个范围卡片，展示样式按原型旧版恢复。
2. 申请处理为三级菜单，包含 `延期审批`、`收回申请`、`短信审核` 三个子功能。
3. 三个申请处理子功能都采用“列表右侧点击处理，弹窗内完成业务动作”的交互模式。
4. 工单状态不新增 `待发送`，短信审核、短信发送记录不改变工单主状态。
5. 固定短信模板可直接发送，短信内容不可编辑，不需要审核；选择 `其他` 时短信内容可编辑，需要点击 `发送审核`。
6. 需要审核的短信提交后在工单联系记录中生成记录，初始为 `未联系`；审核同意后为 `已审核`，拦截后为 `已拦截`，只有同意后才能发送。
7. 短信审核通过记录可在短信弹窗右上角删除；删除或发送完成后，短信弹窗恢复到原编辑状态。
8. 附件上传后需要展示文件记录和删除按钮。
9. 上传附件的提示统一使用 `查看支持上传格式`，支持格式严格按业务截图控制，并提示单个文件不超过 300MB。
10. 台账导出页面为固定高度布局，不出现页面级纵向下滑；工单列表区域固定高度，只保留底部横向滚动。

## 一、角色与权限

### 1. 角色切换

入口：页面右上角角色切换区域。

系统通过角色切换模拟不同用户权限，不同角色看到的菜单、按钮、可操作数据范围不同。切换角色后，应重点观察左侧菜单、列表操作按钮、详情页按钮、后台配置入口是否随角色变化。

| 角色 | 功能范围 |
| --- | --- |
| 超级管理员 | 可进入后台管理，维护角色权限、用户、机构、参数配置；可查看全局配置 |
| 总行消保岗派发员 | 数据范围为全行，主要负责全行工单派发、催办、台账、报表、统计查看，基本不直接处理工单 |
| 总行部室派发员 | 数据范围为本机构，总行不单设处理员，由部室派发员承担派发和处理两类职责 |
| 分行消保岗派发员 | 数据范围为本机构及下辖，负责分行范围内工单派发、催办、台账、报表、统计查看 |
| 投诉处理员 | 数据范围为本机构，处理本人或本机构分配的工单，填写处理结果、提交审核、申请延期、短信联系、回访 |
| 总行领导 | 数据范围为全行，仅查看、查询、导出台账报表统计，不参与处理、派发、审核 |
| 分行领导 | 数据范围为本机构及下辖，仅查看、查询、导出台账报表统计，不参与处理、派发、审核 |

派发与审核规则：

1. 总行消保岗派发员可将工单派给总行部室派发员。
2. 总行部室派发员收到工单后，可以自己处理，也可以继续往下派发。
3. 总行没有单独的处理员角色，部室派发员承担 `派发 + 处理` 两类事项。
4. 审核遵循 `谁最后一次派发，谁审核` 的逻辑。
5. 派发员可以对本人数据范围内 `待处理`、`处理中` 状态的工单进行催办。
6. 分行消保岗派发员与投诉处理员的数据范围不同：分行派发员为本机构及下辖，处理员仅为本机构。

### 2. 机构切换

入口：页面右上角机构切换区域。

机构切换用于模拟账号数据权限。所属机构只能选择一个，借调机构可以选择多个。切换后，报表、台账、工单列表的数据范围应随机构权限变化。

操作规则：

1. 所属机构为账号主机构，只能单选。
2. 借调机构用于临时查看或处理其他机构数据，可以多选。
3. 报表详情、台账导出、工单处理列表应按当前账号机构权限过滤。
4. 切换机构后，页面展示的机构名称、工单数据、统计范围都应刷新。

## 二、投诉管理 - 工单录入

入口：`投诉管理` -> `工单录入`。

工单录入用于创建标准投诉工单，支持自建单、监管转办类工单、客服热线工单等来源。录入页按业务分区展示，包括工单信息、客户信息、投诉信息、附件信息和指派处理。

### 1. 工单信息

主要字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 工单标题，概括客户投诉事项 |
| 工单类型 | 下拉选择，包含投诉、举报、抱怨、咨询、建议、求助、信访等 |
| 投诉反映渠道 | 下拉选择，包含国家局、省监管局、市监管局、政务热线、银行协会、人民银行、宜当生活、客服热线、其它 |
| 渠道细分 | 当渠道需要补充说明时填写，例如其它渠道来源 |
| 监管工单编号 | 监管来源工单需要填写，非监管来源按业务口径可不填 |
| 工单级别 | 普通、重要、紧急；后台字段维护中可配置对应处理时限字段值 |
| 办理时限 | 系统根据工单级别和工作日规则自动计算，只读展示 |
| 是否重办 | 下拉选择是或否 |
| 是否现场 | 下拉选择是或否 |

操作步骤：

1. 进入工单录入页。
2. 选择工单类型。
3. 选择投诉反映渠道。
4. 如选择监管相关渠道，填写监管工单编号。
5. 选择工单级别，查看办理时限是否自动带出。
6. 选择是否重办、是否现场。

业务规则：

1. 投诉反映渠道中的 `客服热线` 用于客服系统导入或客服来源工单识别。
2. 工单级别与处理时限合并维护，普通、重要、紧急的字段值可配置为 `3个工作日`。
3. 办理时限不是人工随意编辑字段，应由系统按配置和节假日规则计算。
4. 监管工单编号是否必填与渠道来源有关。

### 2. 客户信息

主要字段：

| 字段 | 说明 |
| --- | --- |
| 投诉人姓名 | 客户姓名，支持手工录入 |
| 性别 | 下拉选择男、女 |
| 身份证号码 | 用于客户识别、历史投诉查询、贷款查询 |
| 联系电话 | 客户联系电话 |
| 卡号 | 可选，客户提供时填写 |

页面右上角功能：

1. `查询历史投诉`：按客户信息查询历史投诉。
2. `查询贷款信息`：按身份证号码查询贷款信息。

操作步骤：

1. 填写客户姓名、证件号码、联系电话。
2. 点击 `查询历史投诉`。
3. 查看历史投诉列表，必要时点击工单编号进入详情。
4. 点击 `查询贷款信息`。
5. 查看贷款弹窗，存在多笔贷款时通过顶部序号切换。

业务规则：

1. 查询历史投诉和查询贷款信息按钮放在客户信息区域右上角，左右排列。
2. 身份证号码输入框内部不放查询贷款按钮。
3. 工单录入时，手机号和身份证号码至少填写一个。
4. 历史投诉查询中，自建单和客服单合并展示，客服作为渠道来源展示，不单独做客服单列。
5. 贷款查询弹窗只展示贷款详情卡片，不展示底部贷款列表。
6. 贷款弹窗中的无用灰色说明文字应删除。

### 3. 客服热线扩展信息

触发条件：工单渠道来源选择 `客服热线`。

客服系统传入但无法映射到标准工单字段的内容，应展示在客户信息下方的独立扩展信息区。非客服热线渠道不展示该区域。

当前扩展字段示例：

| 字段 |
| --- |
| 来电人 Email |
| 来电人邮编 |
| 联系地址 |
| 业务类型 |
| 工单子类型 |
| 来电业务类型 |
| 处理方式 |
| 是否需要回访 |
| 来电人称谓 |
| 工单类型 |
| 进件渠道 |
| 工单级别 |

业务规则：

1. 客服扩展信息只展示客服传入但系统标准字段映射不上的内容。
2. 扩展信息区不展示一级分类、二级分类。
3. 客服传什么字段就展示什么字段，无值显示 `-`。
4. 切换为非客服热线时，该扩展区域隐藏。

### 4. 投诉信息

主要字段：

| 字段 | 说明 |
| --- | --- |
| 被投诉机构 | 选择或填写被投诉机构，不在后台字段维护中维护 |
| 投诉人诉求 | 下拉选择金钱赔偿、赔礼道歉、返还财产、恢复原状、其他 |
| 投诉内容 | 客户投诉的详细描述 |
| 业务类别 | 业务大类、中类、小类，后台字段维护中平铺维护 |
| 原因类别 | 原因大类、中类、小类，后台字段维护中平铺维护 |
| 投诉产品标签 | AI 打标产品标签，可人工修正 |
| 投诉原因标签 | AI 打标原因标签，可人工修正 |

操作步骤：

1. 填写被投诉机构。
2. 选择投诉人诉求。
3. 填写投诉内容。
4. 点击一键打标，生成投诉产品标签和投诉原因标签。
5. 根据业务实际调整业务类别、原因类别和标签。

业务规则：

1. 产品标签和原因标签属于 AI 打标配置，不和普通字段维护混在一起。
2. 业务类别、原因类别放在字段维护中平铺维护，展示标签名称和父级码值。
3. 投诉内容不能为空，长度按系统字段规则控制。

### 5. 附件信息

附件信息用于上传客户投诉材料、监管转办文件、处理材料等。

操作步骤：

1. 点击上传附件。
2. 选择文件。
3. 上传后在附件列表查看文件名。
4. 点击附件预览。

业务规则：

1. 工单录入、工单处理、回访上传附件处都应保留上传能力。
2. 上传按钮旁展示 `查看支持上传格式`，点击或悬浮后展示支持格式。
3. 支持格式严格为：文档 PDF、DOC、DOCX、TXT；表格 XLS、XLSX、CSV；图片 JPG、JPEG、PNG；音频 MP3、WAV、M4A、AMR；视频 MP4、MOV、AVI、MKV；压缩包 ZIP、RAR、7Z。
4. 提示中展示 `单个文件不超过 300MB`。
5. 附件上传后需要展示文件记录，并提供删除按钮。
6. 附件为空是否允许提交，按业务要求确定。

### 6. 指派处理

主要字段：

| 字段 | 说明 |
| --- | --- |
| 所属机构 | 选择处理机构 |
| 处理人/派发员 | 根据机构和角色选择可承接人员 |

业务规则：

1. 草稿箱编辑后，可以派发到本机构或下辖机构人员。
2. 处理人候选范围应受机构、角色和状态约束。
3. 总行消保岗可派给总行部室派发员；总行部室派发员可处理，也可继续派发。
4. 机构默认接收人接收外部工单后，可手动派发。

## 三、投诉管理 - 草稿箱

入口：`投诉管理` -> `草稿箱`。

草稿箱用于保存未正式派发的工单，包括单笔录入草稿和客服工单草稿。

功能说明：

1. 查看草稿列表。
2. 编辑草稿。
3. 查看草稿详情。
4. 编辑完成后进入派发流程。

页面规则：

1. 草稿箱列表中，单笔录入和客服工单列表都只保留 `编辑`、`查看`。
2. 草稿箱列表不展示 `派发` 按钮。
3. 派发动作应在编辑页完成。
4. 客服单和自建单可在历史投诉查询中合并展示。

操作步骤：

1. 在工单录入页保存草稿。
2. 进入草稿箱。
3. 点击 `查看` 检查草稿详情。
4. 点击 `编辑` 进入录入页继续完善。
5. 在编辑页选择机构和处理人后派发。

## 四、投诉管理 - 工单处理

入口：`投诉管理` -> `工单处理`。

工单处理用于投诉处理员和各类派发员处理待办工单、查看详情、联系客户、提交审核、收回、催办或派发工单。

### 1. 工单列表

列表展示工单编号、标题、渠道、客户、机构、级别、状态、剩余时间、处理人和操作按钮。

常见操作：

| 操作 | 说明 |
| --- | --- |
| 查看 | 查看工单完整详情 |
| 处理 | 投诉处理员对待处理或处理中工单进行处理 |
| 派发 | 派发员将工单派给本机构或数据范围内人员；总行部室派发员也可继续派发 |
| 收回 | 对已派发但需调整的工单收回后重新派发 |
| 延期申请 | 投诉处理员对临期或复杂工单申请延期 |
| 催办 | 派发员对数据范围内待处理或处理中的工单发起催办 |

### 2. 状态流转

| 当前状态 | 操作 | 流转后状态 |
| --- | --- | --- |
| 草稿 | 草稿编辑后派发 | 已派发 |
| 已派发 | 投诉处理员接收 / 确认处理 | 待处理或处理中 |
| 待处理 | 确认处理 | 处理中 |
| 处理中 | 继续派发 | 处理中 |
| 处理中 | 提交审核 | 待审核 |
| 待审核 | 审核通过 | 已办结 |
| 待审核 | 审核退回 | 处理中 |

页面规则：

1. 处理页详情不使用旧状态 `待分配`，应展示 `已派发`、`待处理`、`处理中`、`待审核`、`已办结` 等状态。
2. 状态展示应与列表、详情、流转记录一致。
3. 未办结工单包括已派发、待处理、处理中、待审核等。
4. 短信审核和短信发送不改变工单主状态。

### 3. 工单详情

工单详情页展示工单信息、客户信息、投诉信息、附件信息、处理信息、流转记录等。

工单信息中应展示四个时间字段：

| 时间字段 | 说明 |
| --- | --- |
| 录入时间 | 工单创建或录入系统的时间 |
| 受理时间 | 工单正式受理时间 |
| 办结时间 | 工单审核通过或关闭完成时间 |
| 回访时间 | 客户回访完成或计划回访时间 |

业务规则：

1. 四个时间字段放在工单信息已有字段后面展示。
2. 有真实时间时展示真实时间，没有时间时显示 `-`。
3. 系统内 `关单时间` 和 `办结时间` 统一展示为 `办结时间`。
4. 工单详情页下方不展示非系统字段说明块。
5. 详情页中的灰色说明文字应尽量删除，节省页面空间。
6. 查看、处理、审核、回访等入口进入的工单详情页都应展示四个时间字段。

### 4. 详情页查询功能

工单详情页也提供查询历史投诉和查询贷款信息能力。

操作步骤：

1. 进入查看、处理、审核或回访场景下的工单详情。
2. 点击 `查询历史投诉`。
3. 查看历史投诉列表。
4. 点击 `查询贷款信息`。
5. 查看贷款详情弹窗。

业务规则：

1. 查询功能不仅在录入页存在，工单详情页也要有。
2. 查询历史投诉和贷款信息入口应位置清晰，不影响详情字段阅读。
3. 历史投诉点击编号直接跳转详情页，不使用弹框详情。

### 5. 处理表单

处理表单用于投诉处理员填写最终处理意见。

主要字段：

| 字段 | 说明 |
| --- | --- |
| 处理结论 | 下拉选择 |
| 处理结果 | 文本输入，最多 950 字 |

处理结论选项：

1. `已和客户达成一致`
2. `未达成一致但客户表示理解`
3. `未达成一致`

业务规则：

1. 字段名称保持为 `处理结果`，不要改成 `处理内容`。
2. 处理结果限制 950 字。
3. 提交审核前应填写处理结论和处理结果。
4. 审核通过后，处理结果进入详情只读展示。
5. `处理结果` 下方的 `上传处理附件` 旁展示备注 `可上传沟通记录、证明材料等`。
6. 备注下方保留 `查看支持上传格式` 提示。

### 6. 流转记录

流转记录用于展示工单从录入到办结的完整过程。

字段要求：

| 字段 | 说明 |
| --- | --- |
| 操作时间 | 操作发生时间 |
| 操作人 | 执行操作的用户 |
| 处理机构 | 操作人所在或处理工单的机构，位于操作人后面 |
| 操作类型 | 派发、确认处理、提交审核、审核通过、退回等 |
| 操作内容 | 具体处理说明 |

业务规则：

1. 流转记录必须新增 `处理机构` 列。
2. `处理机构` 位于 `操作人` 后面。
3. 状态变化、短信审核、延期审批、派发收回等都应形成记录。

## 五、投诉管理 - 客户联系与短信

### 1. 联系记录

入口：工单详情页中的联系客户或新增联系记录按钮。

联系记录展示字段：

| 字段 | 说明 |
| --- | --- |
| 联系时间 | 系统记录或手动选择 |
| 触达方式 | 由用户手动填写，不使用固定下拉选项 |
| 答复人姓名 | 联系到的客户或相关人员 |
| 答复群众电话 | 联系电话 |
| 联系结果 | 已联系、未联系、需回访等 |
| 附件 | 电话录音、沟通记录、证明材料等附件 |
| 联系内容 | 沟通内容 |

业务规则：

1. 联系记录保存后应展示在工单详情中。
2. 回访和处理场景都可以使用联系能力。
3. 处理工单信息中的 `新增联系与沟通记录` 改为 `其他沟通方式`。
4. 其他沟通方式弹框中，联系时间、触达方式、答复人姓名、答复群众电话均应单独登记。
5. 其他沟通方式的电话不是必填项。
6. 其他沟通方式允许上传附件，附件上传后可删除。
7. 添加录音文件右侧保留 `添加短信联系` 按钮文案。
8. 无用的说明文字和非系统字段不展示。

### 2. 发送短信

入口：工单处理或回访联系场景中的 `发送短信`。

短信模板当前支持固定模板和 `其他`：

| 模板 | 默认内容 |
| --- | --- |
| 投诉处理联系模板 | 您好，关于您反馈的投诉事项，我行正在处理中，感谢您的理解与配合。 |
| 回访通知模板 | 您好，我行近期将就您反馈的问题进行回访，请保持电话畅通。 |
| 事项告知模板 | 您好，关于您反馈事项的办理情况，我行现向您告知相关进展，请您知悉。 |
| 其他 | 用户手动编辑短信内容，需提交短信审核 |

操作步骤：

1. 打开发送短信弹窗。
2. 选择短信模板。
3. 选择固定模板时，系统自动带出短信内容，内容不可编辑。
4. 选择固定模板时，按钮为 `发送`，不需要短信审核。
5. 选择 `其他` 时，短信内容可编辑，按钮为 `发送审核`。
6. 点击 `发送审核` 后，系统在当前工单联系记录中生成一条短信记录。

业务规则：

1. 下拉框固定包含 `投诉处理联系模板`、`回访通知模板`、`事项告知模板`、`其他`。
2. 下拉框中不能出现消息通知模板，如受理通知、派发通知、审核结果通知等。
3. 固定模板不走审核，直接发送并生成联系记录。
4. `其他` 模板走短信审核，提交后联系记录中的短信状态为 `未联系`。
5. 审核通过后，联系记录中的短信状态为 `已审核`，短信暂存在短信弹窗上方的未发送记录中，再次打开弹窗可点击发送。
6. 审核拦截后，联系记录中的短信状态为 `已拦截`，并保存拦截原因。
7. 审核通过的未发送短信可以删除，删除后恢复原短信编辑页面。
8. 短信发送完成后生成联系记录，并恢复原短信编辑页面。
9. 短信审核和短信发送不改变工单主状态。

## 六、投诉管理 - 申请处理

入口：`投诉管理` -> `申请处理`。

申请处理是投诉管理下的子级目录，包含 `延期审批`、`收回申请`、`短信审核` 三个子功能。三个功能的列表操作保持一致：列表右侧只展示 `处理` 按钮，点击后打开处理弹窗，在弹窗底部完成同意、拦截、收回或不收回等业务动作。

### 1. 延期审批

延期审批用于处理投诉处理员发起的工单延期申请。

延期申请列表字段：

| 字段 | 说明 |
| --- | --- |
| 工单编号 | 行内工单编号 |
| 工单状态 | 当前工单状态 |
| 处理人 | 发起延期申请的处理人员 |
| 申请时间 | 延期申请提交时间 |
| 原处理时限 | 工单当前处理截止时间 |
| 最新处理时限 | 按延期规则计算后的新截止时间 |
| 申请理由 | 投诉处理员填写的延期原因 |
| 操作 | 仅展示 `处理` 按钮 |

操作步骤：

1. 投诉处理员在工单详情页发起延期申请。
2. 填写延期理由，系统生成延期审批记录。
3. 管理人员进入 `申请处理` -> `延期审批`。
4. 列表右侧点击 `处理`。
5. 弹窗展示列表中的申请字段。
6. 点击 `同意`，延期申请通过。
7. 点击 `拦截` 后，弹窗下方新增 `拦截原因` 输入区，填写原因后点击 `确认拦截`。

业务规则：

1. 最新处理时限按工作日顺延，跳过周末和节假日。
2. 同意后，工单处理时限更新。
3. 拦截后，工单处理时限不变，并保存拦截原因。
4. 同意或拦截都应进入历史记录。
5. 处理弹窗底部不展示 `取消` 按钮，关闭弹窗使用右上角 `关闭`。

### 2. 收回申请

收回申请用于处理已派发工单的收回请求，属于 `申请处理` 下独立子功能，不放在延期审批页签内。

收回申请列表字段：

| 字段 | 说明 |
| --- | --- |
| 工单编号 | 行内工单编号 |
| 工单状态 | 当前工单状态 |
| 处理人 | 当前处理人或派发员 |
| 申请时间 | 收回申请提交时间 |
| 申请理由 | 申请收回该工单的原因 |
| 操作 | 仅展示 `处理` 按钮 |

操作步骤：

1. 进入 `申请处理` -> `收回申请`。
2. 查看待处理收回申请列表。
3. 点击列表右侧 `处理`。
4. 弹窗展示工单编号、工单状态、处理人、申请时间、申请理由。
5. 点击 `收回`，该工单收回。
6. 点击 `不收回`，该工单维持当前派发关系。

业务规则：

1. 收回申请不展示 `原处理时限`、`最新处理时限`，这两个字段只属于延期审批。
2. 收回申请弹窗底部不展示 `取消` 按钮，关闭弹窗使用右上角 `关闭`。
3. 收回和不收回都应进入历史记录。

### 3. 短信审核

短信审核用于对投诉处理员提交的客户短信进行合规审核。

操作步骤：

1. 进入短信审核列表。
2. 查看工单编号、处理人、申请时间、短信内容。
3. 列表右侧点击 `处理`。
4. 弹窗展示工单编号、处理人、申请时间、短信模板、接收号码、短信内容。
5. 点击 `同意`，短信审核通过。
6. 点击 `拦截` 后，弹窗下方新增 `拦截原因` 输入区，填写原因后点击 `确认拦截`。

业务规则：

1. 模板名称只能来自后台短信模板配置，例如 `投诉处理联系模板`、`回访通知模板`、`事项告知模板`。
2. 短信审核待审核列表不展示 `短信状态` 列，只展示待审核记录和 `处理` 按钮。
3. 短信审核历史列表展示 `审核结果` 和 `拦截原因`。
4. 审核通过后，状态变为已同意；工单联系记录中的短信记录展示为 `已审核`。
5. 审核拦截后，状态变为已拦截，并保存拦截原因；工单联系记录中的短信记录展示为 `已拦截`。
6. 处理弹窗底部不展示 `取消` 按钮，关闭弹窗使用右上角 `关闭`。
7. 审核动作应写入流转记录或审核记录。

## 七、投诉管理 - 台账导出

入口：`投诉管理` -> `台账导出`。

台账导出用于查询工单明细并导出台账文件，支持按时间类型、日期范围、工单状态等条件筛选。

### 1. 查询条件

常见筛选项：

| 条件 | 说明 |
| --- | --- |
| 客户姓名 | 按投诉人姓名查询 |
| 工单编号 | 按行内工单编号或监管工单编号查询 |
| 工单状态 | 按当前状态筛选 |
| 时间类型 | 录入时间、受理时间、办结时间、回访时间 |
| 开始日期 | 时间范围开始 |
| 结束日期 | 时间范围结束 |

业务规则：

1. 时间类型必须包含四项：录入时间、受理时间、办结时间、回访时间。
2. 不能只展示录入时间。
3. 系统中的关单时间统一为办结时间。

### 2. 台账列表

台账列表应展示工单基础信息、客户信息、处理状态和四个时间字段。

操作步骤：

1. 设置筛选条件。
2. 点击查询。
3. 查看列表结果。
4. 勾选需要导出的工单。
5. 点击 `导出全部台账` 或 `批量导出已选`。

业务规则：

1. 列表分页正常显示。
2. 台账导出页面不出现页面级纵向下滑，筛选区固定在上方，工单列表固定在下方剩余高度中。
3. 工单列表不展示右侧竖向滚动条，只保留底部横向滚动条。
4. 固定高度下每页展示 5 条，避免工单行被底部分页或横向滚动条遮挡。
5. 批量导出已选应受勾选状态控制。
6. 导出全部台账按当前筛选条件导出。

## 八、投诉管理 - 报表管理

入口：`投诉管理` -> `报表管理`。

报表管理用于查看各类投诉工单明细表和统计表。

### 1. 报表详情页

页面要求：

1. 报表详情页顶部不展示面包屑。
2. 标题上方和下方不展示灰色说明小字。
3. 筛选器下方不展示统计范围小字。
4. 页面尽量节省纵向空间。

### 2. 报表页签

常见页签：

| 页签 | 说明 |
| --- | --- |
| 处理状态明细表 | 按工单状态展示明细 |
| 工单类型明细表 | 按投诉、举报、咨询等类型展示 |
| 投诉标签明细表 | 展示产品标签和原因标签 |
| 工单处理统计表 | 展示处理量、办结量、超期等统计 |
| 客服系统统计表 | 展示客服热线相关工单 |
| 监管转办统计表 | 展示监管来源工单 |
| 未办结工单表 | 展示当前未办结工单 |

### 3. 筛选与查询

常见筛选项：

1. 行内工单编号。
2. 录入时间范围。
3. 工单类型。
4. 投诉反映渠道。
5. 工单状态。
6. 被投诉机构或处理机构。

业务规则：

1. 查询后表格刷新。
2. 机构范围受当前账号数据权限控制。
3. 所属机构只有一个，借调机构可以多个。
4. 报表统计应按当前查询条件展示。

## 九、统计分析

入口：`投诉管理` -> `统计分析`。

统计分析用于查看投诉整体趋势、机构分布、产品原因分析、渠道分析和处理效率。

主要模块：

| 模块 | 说明 |
| --- | --- |
| 投诉总览 | 查看投诉量、办结率、超期率、趋势等 |
| 机构分析 | 按机构统计投诉数量、超期、临期等 |
| 产品分析 | 按产品标签统计投诉分布 |
| 原因分析 | 按原因标签统计投诉分布 |
| 渠道分析 | 按投诉反馈渠道统计来源和处理质效 |

业务规则：

1. 渠道分析中不单独展示渠道合计四个字。
2. 客服来源作为渠道来源参与统计。
3. 统计口径应与台账、报表使用的工单数据一致。
4. 已办结、未办结、超期、临期等指标应按工单状态和办理时限计算。

## 十、后台管理 - 用户管理

入口：`后台管理` -> `用户管理`。

用户管理用于维护系统用户、所属机构、角色和职务信息。

主要功能：

1. 查看用户列表。
2. 新增用户。
3. 编辑用户。
4. 启用或停用用户。
5. 配置用户角色和所属机构。

当前重点用户示例：

### 1. 字段维护

入口：`后台管理` -> `参数化配置` -> `字段维护`。

字段维护用于统一维护工单录入页中有下拉选项的字段，不包括 AI 打标使用的投诉产品标签和投诉原因标签。

页面结构：

1. 顶部为筛选条件。
2. 中间栏为字段分类列表。
3. 右侧为当前字段分类下的码值列表。
4. 页面长度固定，内容过多时各区域内部滚动。

筛选条件：

1. 只保留第一个筛选条件。
2. 输入框提示为 `请输入查询的名称或码值`。
3. 可按字段名称、字段值、码值查询。

字段分类：

| 分类 | 说明 |
| --- | --- |
| 工单类型 | 投诉、举报、抱怨、咨询、建议、求助、信访等 |
| 投诉反映渠道 | 国家局、省监管局、市监管局、政务热线、银行协会、人民银行、宜当生活、客服热线、其它 |
| 工单级别 | 普通、重要、紧急，并维护处理时限字段值 |
| 业务归属条线 | 零售金融部、网络金融部等，可多选 |
| 是否重办 | 是、否 |
| 是否现场 | 是、否 |
| 性别 | 男、女 |
| 投诉人诉求 | 金钱赔偿、赔礼道歉、返还财产、恢复原状、其他 |
| 业务类别 | 业务大中小类平铺维护 |
| 原因类别 | 原因大中小类平铺维护 |
| 短信模板配置 | 投诉处理联系模板、回访通知模板、事项告知模板 |

不维护项：

1. 被投诉机构不放在字段维护里。
2. AI 打标的投诉产品标签、投诉原因标签不放在普通字段维护里。

统一列表表头：

| 列名 | 说明 |
| --- | --- |
| 排序 | 原排序字段，可编辑 |
| 字段码值 | 字典码值 |
| 字段名称 | 字典名称，编辑时置灰不可改 |
| 字段值 | 仅工单级别显示处理时限，如 `3个工作日` |
| 父级码值 | 仅业务类别、原因类别显示父级码值 |
| 状态 | 启用或停用，不换行 |
| 操作 | 编辑、禁用，不换行 |

操作步骤：

1. 进入字段维护。
2. 使用筛选框查询字段。
3. 点击中间栏字段分类。
4. 查看右侧码值列表。
5. 点击新增字段值。
6. 填写字段码值、字段名称、排序、状态等。
7. 点击编辑。
8. 修改允许修改的字段。
9. 点击禁用或启用。

编辑规则：

1. 编辑已有字段时，字段名称置灰不可改。
2. 没有字段值的分类，字段值输入框置灰不可改。
3. 没有父级码值的分类，父级码值输入框置灰不可改。
4. 只有工单级别有字段值，展示为 `3个工作日`。
5. 只有业务类别和原因类别有父级码值。
6. 父级码值展示码值，不展示文字名称。
7. 排序字段可以编辑。

业务类别和原因类别规则：

1. 业务类别、原因类别在字段维护中平铺展示。
2. 列表只展示标签名称和父级码值等统一表头字段。
3. 一级标签没有父级码值时展示 `-` 或空值，按页面统一口径处理。
4. 二级、三级标签展示其父级码值。
5. 支持新增、编辑、禁用。

本轮原型重点调整投诉管理、申请处理、客户联系、台账报表和权限口径：

11. 报表管理中宽表使用固定高度表格区域和粘性表头，避免宽表撑开页面。
12. 派发员角色拆分为总行消保岗派发员、总行部室派发员、分行消保岗派发员；领导角色只有查看、查询、导出权限。
