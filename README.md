# 日照银行智慧消保平台投诉原型

本仓库维护日照银行智慧消保平台投诉管理相关的静态 HTML 高保真原型，用于功能演示、业务评审、测试案例编写和后续系统验收。当前原型不是完整前后端工程，直接用浏览器打开 HTML 即可查看。

## 核心文件

| 文件 | 说明 |
| --- | --- |
| `日照银行_智慧消保平台_投诉原型.html` | 主原型文件，GitLab 发布时只同步这个文件 |
| `index.html` | GitHub Pages / 本地入口副本，日常修改后应与主原型完全一致 |
| `README.md` | 项目说明、维护规则、推送流程、系统功能操作手册 |

## 维护规则

1. 修改原型后，保持 `日照银行_智慧消保平台_投诉原型.html` 和 `index.html` 内容一致。
2. HTML 是预编译后的 React 产物，内部使用 `_jsx` / `_jsxs`，不要直接写未编译 JSX。
3. 工作区长期存在一些无关删除和未跟踪文件，提交前必须确认暂存范围。
4. GitHub 主仓库通常提交 `日照银行_智慧消保平台_投诉原型.html`、`index.html`，以及用户明确要求维护的文档。
5. GitLab 镜像仓库只同步并提交 `日照银行_智慧消保平台_投诉原型.html`，不要把 `index.html` 或本 README 带过去。

## 系统功能操作手册

本手册按系统菜单和真实业务操作整理，用于后续编写测试案例、检查功能完整性和进行业务验收。写测试案例时，可以直接按每个模块的“入口、功能说明、操作步骤、业务规则、结果表现”拆分。

## 一、角色与权限

### 1. 角色切换

入口：页面右上角角色切换区域。

系统通过角色切换模拟不同用户权限，不同角色看到的菜单、按钮、可操作数据范围不同。切换角色后，应重点观察左侧菜单、列表操作按钮、详情页按钮、后台配置入口是否随角色变化。

| 角色 | 功能范围 |
| --- | --- |
| 超级管理员 | 可进入后台管理，维护角色权限、用户、机构、参数配置；可查看全局配置 |
| 机构管理员 | 可查看本机构及下辖机构工单，可派发、收回、查看处理情况 |
| 工单派发员 | 可接收外部工单，编辑草稿，派发到本机构或下辖机构人员 |
| 投诉处理员 | 可处理待办工单，联系客户，发送短信，填写处理结果，提交审核，申请延期 |
| 督办人员 | 系统内置督办角色，权限与投诉处理员接近，但派发时不能被选择 |

### 2. 机构切换

入口：页面右上角机构切换区域。

机构切换用于模拟账号数据权限。所属机构只能选择一个，借调机构可以选择多个。切换后，报表、台账、工单列表的数据范围应随机构权限变化。

操作规则：

1. 所属机构为账号主机构，只能单选。
2. 借调机构用于临时查看或处理其他机构数据，可以多选。
3. 报表详情、台账导出、工单处理列表应按当前账号机构权限过滤。
4. 切换机构后，页面展示的机构名称、工单数据、统计范围都应刷新。

## 二、投诉管理 - 工单录入

入口：`投诉管理` -> `工单录入`。

工单录入用于创建标准投诉工单，支持自建单、监管转办类工单、客服热线工单等来源。录入页按业务分区展示，包括工单信息、客户信息、投诉信息、附件信息和指派处理。

### 1. 工单信息

主要字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 工单标题，概括客户投诉事项 |
| 工单类型 | 下拉选择，包含投诉、举报、抱怨、咨询、建议、求助、信访等 |
| 投诉反映渠道 | 下拉选择，包含国家局、省监管局、市监管局、政务热线、银行协会、人民银行、宜当生活、客服热线、其它 |
| 渠道细分 | 当渠道需要补充说明时填写，例如其它渠道来源 |
| 监管工单编号 | 监管来源工单需要填写，非监管来源按业务口径可不填 |
| 工单级别 | 普通、重要、紧急；后台字段维护中可配置对应处理时限字段值 |
| 办理时限 | 系统根据工单级别和工作日规则自动计算，只读展示 |
| 是否重办 | 下拉选择是或否 |
| 是否现场 | 下拉选择是或否 |

操作步骤：

1. 进入工单录入页。
2. 选择工单类型。
3. 选择投诉反映渠道。
4. 如选择监管相关渠道，填写监管工单编号。
5. 选择工单级别，查看办理时限是否自动带出。
6. 选择是否重办、是否现场。

业务规则：

1. 投诉反映渠道中的 `客服热线` 用于客服系统导入或客服来源工单识别。
2. 工单级别与处理时限合并维护，普通、重要、紧急的字段值可配置为 `3个工作日`。
3. 办理时限不是人工随意编辑字段，应由系统按配置和节假日规则计算。
4. 监管工单编号是否必填与渠道来源有关。

### 2. 客户信息

主要字段：

| 字段 | 说明 |
| --- | --- |
| 投诉人姓名 | 客户姓名，支持手工录入 |
| 性别 | 下拉选择男、女 |
| 身份证号码 | 用于客户识别、历史投诉查询、贷款查询 |
| 联系电话 | 客户联系电话 |
| 卡号 | 可选，客户提供时填写 |

页面右上角功能：

1. `查询历史投诉`：按客户信息查询历史投诉。
2. `查询贷款信息`：按身份证号码查询贷款信息。

操作步骤：

1. 填写客户姓名、证件号码、联系电话。
2. 点击 `查询历史投诉`。
3. 查看历史投诉列表，必要时点击工单编号进入详情。
4. 点击 `查询贷款信息`。
5. 查看贷款弹窗，存在多笔贷款时通过顶部序号切换。

业务规则：

1. 查询历史投诉和查询贷款信息按钮放在客户信息区域右上角，左右排列。
2. 身份证号码输入框内部不放查询贷款按钮。
3. 历史投诉查询中，自建单和客服单合并展示，客服作为渠道来源展示，不单独做客服单列。
4. 贷款查询弹窗只展示贷款详情卡片，不展示底部贷款列表。
5. 贷款弹窗中的无用灰色说明文字应删除。

### 3. 客服热线扩展信息

触发条件：工单渠道来源选择 `客服热线`。

客服系统传入但无法映射到标准工单字段的内容，应展示在客户信息下方的独立扩展信息区。非客服热线渠道不展示该区域。

当前扩展字段示例：

| 字段 |
| --- |
| 来电人 Email |
| 来电人邮编 |
| 联系地址 |
| 业务类型 |
| 工单子类型 |
| 来电业务类型 |
| 处理方式 |
| 是否需要回访 |
| 来电人称谓 |
| 工单类型 |
| 进件渠道 |
| 工单级别 |

业务规则：

1. 客服扩展信息只展示客服传入但系统标准字段映射不上的内容。
2. 扩展信息区不展示一级分类、二级分类。
3. 客服传什么字段就展示什么字段，无值显示 `-`。
4. 切换为非客服热线时，该扩展区域隐藏。

### 4. 投诉信息

主要字段：

| 字段 | 说明 |
| --- | --- |
| 被投诉机构 | 选择或填写被投诉机构，不在后台字段维护中维护 |
| 投诉人诉求 | 下拉选择金钱赔偿、赔礼道歉、返还财产、恢复原状、其他 |
| 投诉内容 | 客户投诉的详细描述 |
| 业务类别 | 业务大类、中类、小类，后台字段维护中平铺维护 |
| 原因类别 | 原因大类、中类、小类，后台字段维护中平铺维护 |
| 投诉产品标签 | AI 打标产品标签，可人工修正 |
| 投诉原因标签 | AI 打标原因标签，可人工修正 |

操作步骤：

1. 填写被投诉机构。
2. 选择投诉人诉求。
3. 填写投诉内容。
4. 点击一键打标，生成投诉产品标签和投诉原因标签。
5. 根据业务实际调整业务类别、原因类别和标签。

业务规则：

1. 产品标签和原因标签属于 AI 打标配置，不和普通字段维护混在一起。
2. 业务类别、原因类别放在字段维护中平铺维护，展示标签名称和父级码值。
3. 投诉内容不能为空，长度按系统字段规则控制。

### 5. 附件信息

附件信息用于上传客户投诉材料、监管转办文件、处理材料等。

操作步骤：

1. 点击上传附件。
2. 选择文件。
3. 上传后在附件列表查看文件名。
4. 点击附件预览。

业务规则：

1. 单笔录入、批量导入后的补录、处理环节都应保留附件能力。
2. 支持图片、PDF、Word、Excel 等常见材料的展示或下载。
3. 附件为空是否允许提交，按业务要求确定。

### 6. 指派处理

主要字段：

| 字段 | 说明 |
| --- | --- |
| 所属机构 | 选择处理机构 |
| 处理人 | 选择投诉处理员 |

业务规则：

1. 草稿箱编辑后，可以派发到本机构或下辖机构人员。
2. 处理人候选范围应受机构、角色和状态约束。
3. 督办人员不能被派发选择。
4. 机构默认接收人接收外部工单后，可手动派发。

## 三、投诉管理 - 草稿箱

入口：`投诉管理` -> `草稿箱`。

草稿箱用于保存未正式派发的工单，包括单笔录入草稿和客服工单草稿。

功能说明：

1. 查看草稿列表。
2. 编辑草稿。
3. 查看草稿详情。
4. 编辑完成后进入派发流程。

页面规则：

1. 草稿箱列表中，单笔录入和客服工单列表都只保留 `编辑`、`查看`。
2. 草稿箱列表不展示 `派发` 按钮。
3. 派发动作应在编辑页完成。
4. 客服单和自建单可在历史投诉查询中合并展示。

操作步骤：

1. 在工单录入页保存草稿。
2. 进入草稿箱。
3. 点击 `查看` 检查草稿详情。
4. 点击 `编辑` 进入录入页继续完善。
5. 在编辑页选择机构和处理人后派发。

## 四、投诉管理 - 工单处理

入口：`投诉管理` -> `工单处理`。

工单处理用于投诉处理员、机构管理员、工单派发员处理待办工单、查看详情、联系客户、提交审核、收回或派发工单。

### 1. 工单列表

列表展示工单编号、标题、渠道、客户、机构、级别、状态、剩余时间、处理人和操作按钮。

常见操作：

| 操作 | 说明 |
| --- | --- |
| 查看 | 查看工单完整详情 |
| 处理 | 投诉处理员对待处理或处理中工单进行处理 |
| 派发 | 机构管理员或工单派发员派发到处理人员 |
| 收回 | 对已派发但需调整的工单收回后重新派发 |
| 延期申请 | 投诉处理员对临期或复杂工单申请延期 |

### 2. 状态流转

| 当前状态 | 操作 | 流转后状态 |
| --- | --- | --- |
| 草稿 | 草稿编辑后派发 | 已派发 |
| 已派发 | 投诉处理员接收 / 确认处理 | 待处理或处理中 |
| 待处理 | 确认处理 | 处理中 |
| 处理中 | 继续派发 | 处理中 |
| 处理中 | 提交审核 | 待审核 |
| 待审核 | 审核通过 | 已办结 |
| 待审核 | 审核退回 | 处理中 |

页面规则：

1. 处理页详情不使用旧状态 `待分配`，应展示 `已派发`、`待处理`、`处理中`、`待审核`、`已办结` 等状态。
2. 状态展示应与列表、详情、流转记录一致。
3. 未办结工单包括已派发、待处理、处理中、待审核等。

### 3. 工单详情

工单详情页展示工单信息、客户信息、投诉信息、附件信息、处理信息、流转记录等。

工单信息中应展示四个时间字段：

| 时间字段 | 说明 |
| --- | --- |
| 录入时间 | 工单创建或录入系统的时间 |
| 受理时间 | 工单正式受理时间 |
| 办结时间 | 工单审核通过或关闭完成时间 |
| 回访时间 | 客户回访完成或计划回访时间 |

业务规则：

1. 四个时间字段放在工单信息已有字段后面展示。
2. 有真实时间时展示真实时间，没有时间时显示 `-`。
3. 系统内 `关单时间` 和 `办结时间` 统一展示为 `办结时间`。
4. 工单详情页下方不展示非系统字段说明块。
5. 详情页中的灰色说明文字应尽量删除，节省页面空间。
6. 查看、处理、审核、回访等入口进入的工单详情页都应展示四个时间字段。

### 4. 详情页查询功能

工单详情页也提供查询历史投诉和查询贷款信息能力。

操作步骤：

1. 进入查看、处理、审核或回访场景下的工单详情。
2. 点击 `查询历史投诉`。
3. 查看历史投诉列表。
4. 点击 `查询贷款信息`。
5. 查看贷款详情弹窗。

业务规则：

1. 查询功能不仅在录入页存在，工单详情页也要有。
2. 查询历史投诉和贷款信息入口应位置清晰，不影响详情字段阅读。
3. 历史投诉点击编号直接跳转详情页，不使用弹框详情。

### 5. 处理表单

处理表单用于投诉处理员填写最终处理意见。

主要字段：

| 字段 | 说明 |
| --- | --- |
| 处理结论 | 下拉选择 |
| 处理结果 | 文本输入，最多 950 字 |

处理结论选项：

1. `已和客户达成一致`
2. `未达成一致但客户表示理解`
3. `未达成一致`

业务规则：

1. 字段名称保持为 `处理结果`，不要改成 `处理内容`。
2. 处理结果限制 950 字。
3. 提交审核前应填写处理结论和处理结果。
4. 审核通过后，处理结果进入详情只读展示。

### 6. 流转记录

流转记录用于展示工单从录入到办结的完整过程。

字段要求：

| 字段 | 说明 |
| --- | --- |
| 操作时间 | 操作发生时间 |
| 操作人 | 执行操作的用户 |
| 处理机构 | 操作人所在或处理工单的机构，位于操作人后面 |
| 操作类型 | 派发、确认处理、提交审核、审核通过、退回等 |
| 操作内容 | 具体处理说明 |

业务规则：

1. 流转记录必须新增 `处理机构` 列。
2. `处理机构` 位于 `操作人` 后面。
3. 状态变化、短信审核、延期审批、派发收回等都应形成记录。

## 五、投诉管理 - 客户联系与短信

### 1. 联系记录

入口：工单详情页中的联系客户或新增联系记录按钮。

联系记录展示字段：

| 字段 | 说明 |
| --- | --- |
| 联系时间 | 系统记录或手动选择 |
| 触达方式 | 电话、短信、网络、现场等 |
| 答复人姓名 | 联系到的客户或相关人员 |
| 答复群众电话 | 联系电话 |
| 联系结果 | 已联系、未联系、需回访等 |
| 录音文件 | 电话联系时可关联录音 |
| 联系内容 | 沟通内容 |

业务规则：

1. 联系记录保存后应展示在工单详情中。
2. 回访和处理场景都可以使用联系能力。
3. 无用的说明文字和非系统字段不展示。

### 2. 发送短信

入口：工单处理或回访联系场景中的 `发送短信`。

短信模板只允许选择两个：

| 模板 | 默认内容 |
| --- | --- |
| 投诉处理联系模板 | 您好，关于您反馈的投诉事项，我行正在处理中，感谢您的理解与配合。 |
| 回访通知模板 | 您好，我行近期将就您反馈的问题进行回访，请保持电话畅通。 |

操作步骤：

1. 打开发送短信弹窗。
2. 选择短信模板。
3. 系统自动带出短信内容。
4. 根据需要编辑短信内容。
5. 提交短信审核。

业务规则：

1. 下拉框中不能出现 `其他`。
2. 下拉框中不能出现消息通知模板，如受理通知、派发通知、审核结果通知等。
3. 处理和回访场景都只能选择上述两个短信模板。
4. 短信内容可编辑，但模板来源必须正确。

## 六、投诉管理 - 申请处理

入口：`投诉管理` -> `申请处理`。

申请处理包括短信审核、延期审批等需要管理人员确认的流程。

### 1. 短信审核

短信审核用于对投诉处理员提交的客户短信进行合规审核。

操作步骤：

1. 进入短信审核列表。
2. 查看工单编号、提交人、提交时间、短信模板、短信内容、状态。
3. 点击同意，短信审核通过。
4. 点击拦截，填写拦截原因后提交。

业务规则：

1. 模板名称只能是 `投诉处理联系模板` 或 `回访通知模板`。
2. 审核通过后，状态变为已同意。
3. 审核拦截后，状态变为已拦截，并保存拦截原因。
4. 审核动作应写入流转记录或审核记录。

### 2. 延期审批

延期审批用于处理投诉处理员发起的工单延期申请。

延期申请字段：

| 字段 | 说明 |
| --- | --- |
| 原处理时限 | 工单当前处理截止时间 |
| 延长时间 | 延期天数，例如 15 个工作日 |
| 最新处理时限 | 按工作日计算后的新截止时间 |
| 申请延期理由 | 投诉处理员填写 |

操作步骤：

1. 投诉处理员在工单详情页发起延期申请。
2. 填写延期理由。
3. 管理人员进入延期审批列表。
4. 查看申请详情。
5. 同意或不同意。
6. 不同意时填写不同意理由。

业务规则：

1. 最新处理时限按工作日顺延，跳过周末和节假日。
2. 同意后，工单处理时限更新。
3. 不同意后，工单处理时限不变。
4. 同意或不同意都应进入历史记录。

## 七、投诉管理 - 台账导出

入口：`投诉管理` -> `台账导出`。

台账导出用于查询工单明细并导出台账文件，支持按时间类型、日期范围、工单状态等条件筛选。

### 1. 查询条件

常见筛选项：

| 条件 | 说明 |
| --- | --- |
| 客户姓名 | 按投诉人姓名查询 |
| 工单编号 | 按行内工单编号或监管工单编号查询 |
| 工单状态 | 按当前状态筛选 |
| 时间类型 | 录入时间、受理时间、办结时间、回访时间 |
| 开始日期 | 时间范围开始 |
| 结束日期 | 时间范围结束 |

业务规则：

1. 时间类型必须包含四项：录入时间、受理时间、办结时间、回访时间。
2. 不能只展示录入时间。
3. 系统中的关单时间统一为办结时间。

### 2. 台账列表

台账列表应展示工单基础信息、客户信息、处理状态和四个时间字段。

操作步骤：

1. 设置筛选条件。
2. 点击查询。
3. 查看列表结果。
4. 勾选需要导出的工单。
5. 点击 `导出全部台账` 或 `批量导出已选`。

业务规则：

1. 列表分页正常显示。
2. 列表内容过多时页面可滚动。
3. 批量导出已选应受勾选状态控制。
4. 导出全部台账按当前筛选条件导出。

## 八、投诉管理 - 报表管理

入口：`投诉管理` -> `报表管理`。

报表管理用于查看各类投诉工单明细表和统计表。

### 1. 报表详情页

页面要求：

1. 报表详情页顶部不展示面包屑。
2. 标题上方和下方不展示灰色说明小字。
3. 筛选器下方不展示统计范围小字。
4. 页面尽量节省纵向空间。

### 2. 报表页签

常见页签：

| 页签 | 说明 |
| --- | --- |
| 处理状态明细表 | 按工单状态展示明细 |
| 工单类型明细表 | 按投诉、举报、咨询等类型展示 |
| 投诉标签明细表 | 展示产品标签和原因标签 |
| 工单处理统计表 | 展示处理量、办结量、超期等统计 |
| 客服系统统计表 | 展示客服热线相关工单 |
| 监管转办统计表 | 展示监管来源工单 |
| 未办结工单表 | 展示当前未办结工单 |

### 3. 筛选与查询

常见筛选项：

1. 行内工单编号。
2. 录入时间范围。
3. 工单类型。
4. 投诉反映渠道。
5. 工单状态。
6. 被投诉机构或处理机构。

业务规则：

1. 查询后表格刷新。
2. 机构范围受当前账号数据权限控制。
3. 所属机构只有一个，借调机构可以多个。
4. 报表统计应按当前查询条件展示。

## 九、统计分析

入口：`投诉管理` -> `统计分析`。

统计分析用于查看投诉整体趋势、机构分布、产品原因分析、渠道分析和处理效率。

主要模块：

| 模块 | 说明 |
| --- | --- |
| 投诉总览 | 查看投诉量、办结率、超期率、趋势等 |
| 机构分析 | 按机构统计投诉数量、超期、临期等 |
| 产品分析 | 按产品标签统计投诉分布 |
| 原因分析 | 按原因标签统计投诉分布 |
| 渠道分析 | 按投诉反馈渠道统计来源和处理质效 |

业务规则：

1. 渠道分析中不单独展示渠道合计四个字。
2. 客服来源作为渠道来源参与统计。
3. 统计口径应与台账、报表使用的工单数据一致。
4. 已办结、未办结、超期、临期等指标应按工单状态和办理时限计算。

## 十一、后台管理 - 角色权限管理

入口：`后台管理` -> `角色权限管理`。

角色权限管理用于维护系统角色及菜单、按钮、数据权限。

主要角色：

1. 超级管理员。
2. 机构管理员。
3. 工单派发员。
4. 投诉处理员。
5. 督办人员。

督办人员规则：

1. `督办人员` 为系统内置角色。
2. 督办人员权限与投诉处理员一致。
3. 派发工单时不能选择督办人员。
4. 督办人员用于接收分行确认处理后的通知，例如分管行领导、分行行长、分行消保负责人。

## 十二、后台管理 - 机构管理

入口：`后台管理` -> `机构管理`。

机构管理用于维护组织机构层级、机构状态和工单默认接收人。

列表字段：

| 字段 | 说明 |
| --- | --- |
| 机构名称 | 总行、分行、支行、网点等 |
| 上级机构 | 当前机构的上级 |
| 机构层级 | 总行、分行、支行等 |
| 工单默认接收人 | 接收外部工单的默认人员 |

1. 进入机构管理。
2. 查看机构列表。
3. 点击编辑。

## 十三、后台管理 - 参数化配置

入口：`后台管理` -> `参数化配置`。

参数化配置用于维护系统字典、标签、短信模板和节假日数据。

### 1. 字段维护

入口：`后台管理` -> `参数化配置` -> `字段维护`。

字段维护用于统一维护工单录入页中有下拉选项的字段，不包括 AI 打标使用的投诉产品标签和投诉原因标签。

页面结构：

1. 顶部为筛选条件。
2. 中间栏为字段分类列表。
3. 右侧为当前字段分类下的码值列表。
4. 页面长度固定，内容过多时各区域内部滚动。

筛选条件：

1. 只保留第一个筛选条件。
2. 输入框提示为 `请输入查询的名称或码值`。
3. 可按字段名称、字段值、码值查询。

字段分类：

| 分类 | 说明 |
| --- | --- |
| 工单类型 | 投诉、举报、抱怨、咨询、建议、求助、信访等 |
| 投诉反映渠道 | 国家局、省监管局、市监管局、政务热线、银行协会、人民银行、宜当生活、客服热线、其它 |
| 工单级别 | 普通、重要、紧急，并维护处理时限字段值 |
| 业务归属条线 | 零售金融部、网络金融部等，可多选 |
| 是否重办 | 是、否 |
| 是否现场 | 是、否 |
| 性别 | 男、女 |
| 投诉人诉求 | 金钱赔偿、赔礼道歉、返还财产、恢复原状、其他 |
| 业务类别 | 业务大中小类平铺维护 |
| 原因类别 | 原因大中小类平铺维护 |
| 短信模板配置 | 投诉处理联系模板、回访通知模板 |

不维护项：

1. 被投诉机构不放在字段维护里。
2. AI 打标的投诉产品标签、投诉原因标签不放在普通字段维护里。

统一列表表头：

| 列名 | 说明 |
| --- | --- |
| 排序 | 原排序字段，可编辑 |
| 字段码值 | 字典码值 |
| 字段名称 | 字典名称，编辑时置灰不可改 |
| 字段值 | 仅工单级别显示处理时限，如 `3个工作日` |
| 父级码值 | 仅业务类别、原因类别显示父级码值 |
| 状态 | 启用或停用，不换行 |
| 操作 | 编辑、禁用，不换行 |

操作步骤：

1. 进入字段维护。
2. 使用筛选框查询字段。
3. 点击中间栏字段分类。
4. 查看右侧码值列表。
5. 点击新增字段值。
6. 填写字段码值、字段名称、排序、状态等。
7. 点击编辑。
8. 修改允许修改的字段。
9. 点击禁用或启用。

编辑规则：

1. 编辑已有字段时，字段名称置灰不可改。
2. 没有字段值的分类，字段值输入框置灰不可改。
3. 没有父级码值的分类，父级码值输入框置灰不可改。
4. 只有工单级别有字段值，展示为 `3个工作日`。
5. 只有业务类别和原因类别有父级码值。
6. 父级码值展示码值，不展示文字名称。
7. 排序字段可以编辑。

业务类别和原因类别规则：

1. 业务类别、原因类别在字段维护中平铺展示。
2. 列表只展示标签名称和父级码值等统一表头字段。
3. 一级标签没有父级码值时展示 `-` 或空值，按页面统一口径处理。
4. 二级、三级标签展示其父级码值。
5. 支持新增、编辑、禁用。

### 2. 短信模板配置

入口：`后台管理` -> `参数化配置` -> `字段维护` -> `短信模板配置`。

短信模板配置属于字段维护下的二级内容，不是消息通知模板。

当前两个模板：

| 模板名称 | 短信内容 |
| --- | --- |
| 投诉处理联系模板 | 您好，关于您反馈的投诉事项，我行正在处理中，感谢您的理解与配合。 |
| 回访通知模板 | 您好，我行近期将就您反馈的问题进行回访，请保持电话畅通。 |

功能说明：

1. 查看短信模板列表。
2. 新增短信模板。
3. 编辑短信模板名称和内容。
4. 启用或禁用短信模板。

业务规则：

1. 页面中不展示消息通知模板。
2. 不展示受理通知、派发通知、审核结果通知等消息通知类模板。
3. 工单处理和回访发送短信时，只能选择这里维护的短信模板。
4. 列表内容过多时可滚动。

### 3. 投诉产品标签

入口：`后台管理` -> `参数化配置` -> `投诉产品标签`。

投诉产品标签用于 AI 打标，不属于普通字段维护。

功能说明：

1. 查看产品标签层级。
2. 新增标签。
3. 编辑标签。
4. 删除或禁用标签。

业务规则：

1. 标签用于投诉内容智能识别。
2. 修改标签会影响 AI 打标结果。
3. 标签层级应保持业务口径稳定。

### 4. 投诉原因标签

入口：`后台管理` -> `参数化配置` -> `投诉原因标签`。

投诉原因标签用于 AI 打标，不属于普通字段维护。

功能说明：

1. 查看原因标签层级。
2. 新增标签。
3. 编辑标签。
4. 删除或禁用标签。

业务规则：

1. 标签用于投诉原因智能识别。
2. 修改标签名称或层级关系会影响打标准确度。
3. 原因标签和字段维护中的原因类别不是同一个维护入口。

### 5. 节假日维护

入口：`后台管理` -> `参数化配置` -> `节假日维护`。

节假日维护用于办理时限计算，系统根据工作日历跳过周末和节假日。

功能说明：

1. 查看节假日列表。
2. 查看分页器。
3. 滚动节假日列表。
4. 导入节假日 Excel。

业务规则：

1. 页面长度固定，列表内容过多时内部滚动。
2. 分页器必须正常展示。
3. 导入节假日后，工作日计算应使用最新配置。
4. 延期审批、办理时限计算都依赖节假日维护。

## 十四、消息提醒与个人中心

入口：页面右上角消息提醒图标、个人中心入口。

### 1. 消息提醒

功能说明：

1. 展示待办消息、审核消息、超期提醒、派发提醒等。
2. 点击消息可跳转对应工单详情或申请处理页面。
3. 支持已读、未读状态展示。

交互规则：

1. 点击消息提醒后打开弹窗。
2. 鼠标在弹窗内移动或操作时，弹窗不能关闭。
3. 鼠标离开弹窗区域后，弹窗关闭。
4. 弹窗不能一直停留，也不能刚打开就因为鼠标移动消失。

### 2. 个人中心

功能说明：

1. 展示当前用户信息。
2. 展示当前角色和机构信息。
3. 提供个人相关操作入口。

交互规则：

1. 点击个人中心后打开弹窗。
2. 鼠标在弹窗内可正常操作。
3. 鼠标离开弹窗区域后关闭。
4. 行为应与消息提醒弹窗一致。

## 十五、常用回归检查清单

每次改原型后，建议至少检查以下内容：

1. 两个 HTML 是否一致。
2. 页面能否正常打开。
3. 左侧菜单是否正常切换。
4. 角色切换后权限是否正确。
5. 工单录入页字段是否完整。
6. 工单详情页四个时间字段是否展示。
7. 工单处理状态是否没有旧的 `待分配`。
8. 处理结果是否仍叫 `处理结果`，且限制 950 字。
9. 短信模板是否只有两个。
10. 字段维护表头、滚动、编辑置灰、状态不换行是否正常。
11. 节假日维护分页器和滚动是否正常。
12. 台账导出四个时间字段是否展示。
13. 报表详情是否无面包屑和灰色说明文字。
14. 消息提醒和个人中心悬浮层是否能操作并在鼠标移出后关闭。

## 已知原型约束

1. 当前是静态 HTML 原型，不是真实后端系统。
2. 页面数据大多为前端模拟数据，保存、审核、导出等操作用于演示交互和业务口径。
3. 部分配置联动在原型中通过本地状态模拟，刷新页面后不一定保留。
4. 贷款查询、历史投诉查询、客服扩展字段均为模拟外部接口返回效果。
5. 编写测试案例时，应区分“原型展示效果”和“真实系统接口能力”。
